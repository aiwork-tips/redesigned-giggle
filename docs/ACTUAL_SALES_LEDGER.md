# Export Scout v5.2 — 実仕入れ・実売の収支記録

## 何ができるか

- 1商品・1点ごとに国内仕入れの支払額・日付を記録
- 在庫が売れるまで利益に計上しない
- 売れたときは販売手数料・換金後の**実受取額（円）**と、まだ控除されていない海外送料・その他費用を記録
- **記録上の実現利益 = 実受取額 − 仕入れ総額 − 実受取額から差し引かれていない海外送料 − その他費用**
- 同一SKUで2回以上売却したとき、記録上の累計利益がプラスなら「2回以上売却・合計黒字」を表示
- 在庫として残っている商品の仕入れ原価、月別利益、型番別利益を表示
- CSVで履歴を保存できる

## 重要な区別

`assets/repeatability.js` の「継続調査優先」は**想定価格に基づく仮評価**。

`assets/sales_ledger.js` の「売却済み」は**利用者が入力した実取引の記録**。プラットフォームとの通信による入金検証・実売証明は行っていないため、eBayで入金済みであることをアプリが自動確認したわけではない。

成約時の買い手が支払った総額 USD と、セラーが実際に受け取った円額は異なる。売上総額を「実受取額」に記入すると、販売手数料の抜け漏れが起きるので注意。

販売時の為替レート、決済・プラットフォーム手数料がすでに差し引かれた入金額を使う。海外送料や返品費用もすでに入金額から差し引かれている場合は二重控除しないこと。

返金・返品・税金・関税・消費税・残高調整・在庫評価・共同事業の利益配分などを網羅する正式な会計帳簿ではない。未売却品を含む期末の損益や確定申告をこれだけで完結させない。

## 保存と共有

- 保存先: このブラウザの `localStorage`、キー `export-scout-sales-ledger-v1`
- 既存候補 `export-scout-items-v1`、調査待ち `export-scout-trend-inbox-v1`、仮評価 `export-scout-repeatability-v1` には触れない
- 他の人の端末とは同期しない（3人運用で同じ最新データになるわけではない）
- CSV出力はバックアップであり、自動共有・復元やCSV再取込機能ではない。端末のデータ消去前にCSVを保存する
- 元データに読み込めない取引があるときは誤って上書きしないよう保存・削除を停止する
- SKU（型番・仕様・状態）は記入者が統一する必要がある。同じ商品でも表記が異なる場合、別商品として集計する
