# Export Scout v5.3 | 実績ランキングと将来のFirebase移行

## 実績ランキング（現段階）
- データ元は**このブラウザに保存された手入力の取引履歴** `export-scout-sales-ledger-v1` のみ。
- 商品型番・状態の表記を揃えたSKUで集計。「未売却」は利益・販売回数のランキングに含まない。
- 表示・並び替え：実現利益の合計／売却回数／1回あたりの平均利益。別途、赤字販売回数・未売却在庫・仕入れ日数も表示。
- 継続性の参考条件は **異なる2日以上の仕入れ・2回以上の売却・累計黒字**。実績として表示するには、実際のeBay明細との外部照合をしていないので **自己入力・未監査** を明示する。
- 1回の高額取引が利益順位で上位になっても、それだけで継続的な需要や再仕入れの再現性を証明しない。
- 破損した保存履歴がある場合は部分的なランキングを信じて表示せず、確認を促す。
- 税金、返品、チャージバック、3人への分配などを含む正式な会計損益ではない。

## 全体JSONバックアップ
- `assets/migration_backup.js` は以下の既存ブラウザ領域のみ読み出す（外部に送信しない）:
  - `export-scout-items-v1`（旧保存候補）
  - `export-scout-trend-inbox-v1`（調査待ち）
  - `export-scout-repeatability-v1`（継続調査の仮評価）
  - `export-scout-sales-ledger-v1`（売却・在庫履歴）
  - `export-scout-defaults-v1`（設定）
  - `export-scout-fx-usdjpy-v1`（参考為替キャッシュ）
  - `export-scout-reviewed-v1`（調査進捗）
- JSON形式：`{ format: "export-scout-local-backup", schema_version: 1, exported_at: ISO8601, storage_format: "localStorage-raw-JSON-strings", stores: { [key]: rawJsonString }, invalid_json_keys: [...] }`
- 既存データの生JSON文字列を**改変せず**保存。壊れたJSONも勝手に削除せず保護する。
- このバックアップは現時点で復元・取り込み機能がないので、ダウンロードできるだけ。Firebaseへのアップロード機能でもない。
- 個人の仕入れ・販売情報が含まれるため、公開リポジトリやSNSに絶対にアップロードしない。3人のデータ同期にもならない。
- ブラウザの保存域はサイトのURL別。旧サイトのバックアップを取る**前に**旧サイトを削除しない。

## Firebase移行時の実装計画（未着手）
1. 3人それぞれのユーザー認証と、許可されたメンバーだけが読取・書込できるFirestore Security Rulesを設計・検証。
2. 既存JSONの**読み取り専用プレビュー**とバリデーションを用意し、書込前に件数・内容の一致と競合を確認。インポートはユーザーの明示操作でのみ実行。
3. SKU表記揺れと重複取引IDを解決。ユーザーIDと元端末識別子で衝突しないIDを作成し、旧ブラウザの取引を失わない。
4. アプリのデータ読み書きを `storageAdapter` 等へ分離し、現行localStorage版とFirebase版の両方で回帰テスト。
5. 旧GitHub Pages版のデータと照合・バックアップ完了まで削除せず並行運用。共同管理に移るときだけ切替。
6. 月額費用／無料枠／商用利用ポリシー／API使用条件を移行直前に再確認する。

今は**Firebaseへ接続していない**。機能を移植しやすいように、まず旧保存領域の安全なバックアップと自己入力実績の集計を追加した段階。
